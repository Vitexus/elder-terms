# plan8：boxrig 0.5.0への更新と端末の選択操作

作成日：2026年10月22日

## 目的と今回の作業範囲

端末の文字選択を灰色の塗りつぶしで表示し、ESCで解除できるようにします。通常選択に加え、Ctrl＋ドラッグによるブロック選択も対象です。本文を選ぶ処理にはboxrig 0.5.0を使い、クリック、リンク起動、スクロールとの組み合わせをelder-terms側で整えます。

計画作成時の依頼では、boxrigの参照更新と本計画の保存までを実施しました。その後の実施依頼に従い、段階1以降を順に進めます。進捗と検証結果は、本書の実施記録へ追記します。

調査の基点はelder-termsの`2413a27d`です。`deps/boxrig`は、0.4.0の`032efb05894cd8b629f4d340d6353b4ffb2cda0e`から、公開タグ0.5.0の`bba72066329e75f9e8e2adf180a041ad31911477`へ更新します。上流リポジトリのタグと照合済みです。

## 現在の実装で確認したこと

通常選択は、始点と終点の間を本文の順序で選ぶ操作です。ブロック選択は、画面上の列をそろえて行ごとの矩形を選ぶ操作で、boxrigのAPIでは矩形選択と呼ばれます。PRIMARYは選択完了時に登録して中央ボタンで貼り付ける領域、CLIPBOARDはコピー操作で登録する領域です。

boxrigでは、要求した選択や本文を取得できない状態を`UNAVAILABLE`と表します。`STALE`は、保持した文字位置や範囲が元の本文・配置を指さなくなった失効状態です。

| 対象 | 現在の動作 | 本計画での扱い |
| --- | --- | --- |
| [terminal-presentation.cpp](../../../elder-terms-terminal/src/terminal-presentation.cpp) | カーソル、色補正、背景を設定するが、選択スタイルは設定しない | boxrig既定の青い輪郭を、アプリの灰色の塗りへ変更する |
| 同ファイルの`route_key()` | コピー・貼り付け、BREAK、ズームを処理する。ESCのキー値変換はあるが、選択解除はない | IMEの変換を優先し、その後に選択解除を判定する |
| [terminal-runtime.cpp](../../../elder-terms-terminal/src/terminal-runtime.cpp)の`route_mouse()` | 左ボタンを押した時点で文字選択を開始する | 単一クリックとドラッグを区別する |
| 同関数のリンク処理 | Ctrl＋左ボタンの押下でリンクを起動し、矩形選択より先に処理する | 起動をボタン解放まで保留し、ドラッグなら矩形選択にする |
| 同関数の選択更新 | `inside_grid`のときだけ終点を更新する。選択中はホイール処理にも進まない | 端での終点更新、ホイール、自動スクロールを追加する |
| 同関数の選択終了 | PRIMARYへのコピーで`UNAVAILABLE`と`STALE`を許容する | 既存の適切な扱いを保ち、空の矩形と取消後の解放を検証する |
| [main-window.cpp](../../../elder-terms-terminal/src/main-window.cpp) | Copyの有効判定は、通常範囲と矩形の行数・列幅を分けている | この区分を保ち、0.5.0の空・失効状態も検証する |
| [terminal-color-filter.cpp](../../../shared/src/terminal-color-filter.cpp) | Oklch、5種類の反転、色覚補助を描画時に適用する | 選択の塗りと文字にも既存の色補正を適用する |

灰色表示とESC解除は、elder-termsで操作方針を設定する課題です。boxrigの既存APIで塗りと解除を指定できます。ブロック選択の幅ゼロや履歴の保持は、0.5.0で改善された選択処理を利用します。[選択装飾の公式説明][boxrig-decorations]、[選択の公式説明][boxrig-text]

VTEは、選択の文字色と背景色を指定しない場合、元の文字色と背景色を交換します。常に同じ灰色になる仕様ではありません。本計画では依頼された灰色の塗りとESC解除をelder-termsの操作として定義します。VTEのすべての既定動作を再現することは範囲に含めません。[VTEの選択色API][vte-highlight]

## boxrig 0.5.0に任せる範囲

選択本文の保持、文字境界への対応、表示範囲への描画はboxrigに任せます。elder-termsが文字列を列数で切ったり、矩形の各行を独自にコピーしたりする処理は追加しません。モデルは端末の状態を表示へ同期するboxrigの部品です。履歴のうち画面に表示する範囲をviewportと呼びます。

0.5.0では、矩形の左右の列境界が一致しても始点が残ります。`get_selection()`はtrueを返しますが、幅・行数・範囲数は0で、コピーは`BOXRIG_UI_UNAVAILABLE`です。そこから左右へ動かすと選択を続けられます。空になったことを、ドラッグ終了や選択解除と同一視しません。[公式説明][boxrig-text]、[公開APIコメント][boxrig-view]

矩形の始点は論理行IDと物理行の開始位置で保持されます。物理行は、折り返しによって分かれた画面上の1行です。選択は保持中の履歴まで伸ばせます。GTK3の描画部品には、画面外の文字配置を調べる部品も接続されるため、アプリ独自の解析部品を登録する必要はありません。[公式説明][boxrig-text]

画面内の行番号を使う場合は、対応する`*_visual_row_valid`も確認します。false時の数値0を、画面の先頭行と解釈してはいけません。`range_valid`は通常選択の範囲に対する値で、矩形の有無を示す値ではありません。[選択構造体のAPIコメント][boxrig-view]

hit testとは、ポインター位置をその時点の文字配置へ対応させる問い合わせです。スクロール後はモデルと表示を同期し、新しいhit testで終点を求めます。保持した古い結果の世代番号を書き換えて再利用しません。選択行の書き換え、履歴からの削除、列数・フォント・文字配置の変更による`STALE`も尊重します。[選択更新のAPIコメント][boxrig-view]

新しい解析APIの実装、boxrigのソース変更、SDK外のサンプルヘルパーの組み込みは、この計画には含めません。追加のAPI不足が実装時に判明した場合は、再現結果とともに本計画を見直します。

## 利用者から見た操作

以下は端末の本文領域での操作です。

| 操作・状態 | 実装後の動作 |
| --- | --- |
| 左ボタンの単一クリック | 既存の選択を解除する。1文字だけの選択やPRIMARYへのコピーは行わない |
| 左ドラッグ | 押し始めた位置から通常選択する |
| ダブルクリック／トリプルクリック | 既存どおり単語／行を選び、押したまま範囲を伸ばせる |
| Ctrl＋左ドラッグ | 矩形を選ぶ。途中でCtrlを離しても、そのドラッグの形は変えない |
| Ctrl＋リンクの単一クリック | 同じリンク上で解放した場合に1回だけ起動する |
| Ctrl＋リンク上からのドラッグ | リンクを起動せず、押し始めた位置から矩形を選ぶ |
| Ctrl＋Shift＋左ドラッグ | リンク上でも矩形を選ぶ。リンク起動の候補にはしない |
| マウス通知を有効にした端末内アプリ | 修飾なしの操作を端末へ渡す。Shiftで通常選択、Ctrlで矩形選択を優先する |
| 選択または選択の押下待機がある状態のESC | 選択とドラッグを解除し、ESCを接続先へ送らない |
| IMEの変換中のESC | IMEへ渡して変換を取り消す。端末の選択解除は次のESCで行う |
| 選択のない状態のESC | 既存のショートカットと端末入力の経路へ渡す |
| 選択を伸ばしている間のホイール | 履歴をスクロールし、同じ始点から終点を更新する |
| 選択操作中でないCtrl＋ホイール | 既存どおり文字サイズを変更する |
| 選択完了時の左ボタン解放 | 有効で空でない選択だけをPRIMARYへ登録する |
| Copy／Ctrl＋Shift＋C | 有効で空でない選択をCLIPBOARDへ登録する |

Ctrl付きの複数回クリックは、矩形の文字選択として扱います。矩形の単語・行選択はboxrigで提供されていません。通常選択のダブルクリックとトリプルクリックは保ちます。[選択開始のAPIコメント][boxrig-view]

右クリックのメニュー、中央ボタンの貼り付け、通常のキー入力、通信とログの仕様は保ちます。ドラッグ中にメニューや別の操作へ移る場合は、そのドラッグを中止してから既存の操作へ進みます。

### 灰色の塗りと色補正

通常選択と矩形選択は共通のスタイルです。`boxrig_ui_selection_style_default()`で初期化し、`BOXRIG_UI_SELECTION_FILL`、背景`#b3b3b3`、背景の不透明度255、文字色`#000000`を指定します。文字色の方針は`BOXRIG_UI_SELECTION_FOREGROUND_RGB`です。塗りだけを使う場合でも、初期値の正の線幅を保持します。[装飾のAPIコメント][boxrig-decoration-api]

このRGBは色補正前の値です。既存のフィルタを通した後の灰色は、反転方式などに応じて変わります。塗りはセルの背景色として処理されるため、輪郭の`SELECTION_MARKER`だけを検証しても十分ではありません。選択中の文字と塗りを、実際の描画結果で確認します。[色補正の公式説明][boxrig-colors]、[装飾のAPIコメント][boxrig-decoration-api]

接続別背景、明暗の配色、Oklch、反転A〜E、色覚補助との組み合わせを対象にします。反転A〜Eは、[READMEに記載した既存の5方式](../../../README_ja.md#背景と文字の明暗を反転する)です。文字色・塗りの差を確認し、非選択の範囲や既存フィルタの性質は保ちます。フォーカス移動後も同じ塗りであることが条件です。ウィジェットの再作成や描画方式の復旧時にも、同じスタイルを再適用します。

新しい配色設定画面や保存キーは追加しません。文字のconceal属性と点滅による非表示を尊重し、選択によって隠れた文字を露出させないことも確認します。表示色の変更でコピー本文、端末が保持する色、送受信データ、ログは変えません。

### ESC、IME、押したままの入力

選択の解除判定は、製品と`boxrig-driver`で共有できるruntimeの操作にまとめます。presentation側のキー処理から呼び、ドライバーだけに別の解除処理を作りません。

ESCの初回押下では、Shift、Ctrl、Alt、Superなどの操作用修飾キーがないことを確認します。Caps Lockなどのロック状態だけで解除不能にしません。まず、IMEの未確定文字を保持するcompositionの`active`と`commit_pending`を調べます。IMEの処理中は既存のIME経路を通す方針です。boxrigのGTK3ウィジェットへ届いたキーは、アプリのキールーターがIMEより先に処理するため、この判定が必要です。[compositionのAPIコメント][boxrig-composition]、[GTK3のキー配送][boxrig-gtk-input]

GTKのIMEモジュールが、ウィジェットへの配送より先にキーを消費する経路は例外です。段階2の比較試験で、IBusのkey snooperがこの経路を使うことを確認しました。このキーはアプリへ届かないため、IMEの消費を優先します。アプリから環境変数やIMEモジュールを書き換えて配送を強制する変更は加えません。検証では先行処理の有無を分け、選択解除の結果を混同しない方針に計画を補足します。[IBusの先行処理と環境設定][ibus-snooper]

IMEが処理中でなければ、表示先の選択とruntimeの押下待機・ドラッグ状態を確認します。解除対象は、通常選択、矩形、幅ゼロの矩形、失効した選択です。`boxrig_ui_view_clear_selection()`とホスト側の状態解除を一つの操作として扱います。

取り消したESCは`BOXRIG_INPUT_KEY_ROUTE_APPLICATION`へ振り分けます。boxrigはその初回押下に続くリピートと解放も捕捉するため、解除後に選択がなくなってもESCの残りを接続先へ送りません。通常の端末入力と、キー解放を送る拡張キーボードモードの両方で確認します。[入力ルーターのAPIコメント][boxrig-input]

左ボタンを押したまま取り消した場合は、対応する左ボタン解放まで取消済みの状態を保ちます。移動や解放で選択が復活したり、PRIMARYが更新されたり、リンクが起動したりしないようにします。すでに登録したPRIMARYとCLIPBOARDの内容は、選択解除で消しません。

### クリックとドラッグの判別

runtimeでは、操作なし、単一クリックの押下待機、選択中、取消後の解放待ちを区別します。押下時の座標、修飾キー、クリック回数、リンク候補と文字位置を、所有期間の明確な値として保持します。選択本文の範囲はboxrigが保持し、ホスト側には重複して作りません。

単一クリックの押下では既存選択を解除し、ドラッグ開始の判定を待ちます。GTKのドラッグ距離の設定を使い、閾値を超えたら押下位置から選択を開始して現在位置まで伸ばします。画素座標とGTKの座標の尺度をそろえるため、表示倍率1と2での検証が必要です。[GTKのドラッグ判定][gtk-drag]

Ctrlだけを押したリンク操作は、単一クリックの候補として保持します。解放時にも同じリンクが有効で、ドラッグに変わっていない場合だけ起動します。正規表現で検出するリンクと、端末出力で指定するOSC 8のリンクの双方が対象です。本文更新、ルール変更、画面切り替えで対象が変わった場合は、保存した古いリンクを起動しません。

ドラッグを始める前に保存したhit testが失効した場合は、その押下を中止します。新しい座標から別の文字を始点に選び直すことはしません。ドラッグ開始後の履歴移動は、boxrigの安定した始点を使います。ダブルクリックとトリプルクリックによる単語・行の選択は、押下時からの開始です。

アプリが開始したボタン操作は、解放までアプリが扱います。boxrigにも同じ捕捉契約がありますが、ホスト側の取消済み状態は選択の再開や副作用を防ぐために必要です。端末内アプリがマウス通知を有効にした状態で、押下・移動・解放が混在して送信されないことを検証します。[入力ルーターのAPIコメント][boxrig-input]

### 端での選択と履歴へのスクロール

選択中にポインターが左右へ外れた場合は、最初または最後の列境界へ終点を寄せます。上下へ外れた場合は表示端へ寄せ、自動スクロールを開始します。元の座標を残すのは、スクロール方向の判定に必要なためです。文字位置は有効な表示端の座標で新たに問い合わせます。

スクロールには、既存のスクロールバーモデルと表示更新を使う方針です。モデルの同期と配置の確定後にhit testをやり直して終点を更新します。同じcallbackの中で`frame()`を再入させたり、古い行番号を新しいviewportへ当てはめたりしません。[スクロールの公式説明][boxrig-scrollbars]、[GTK連携の公式説明][boxrig-gtk]

自動スクロールは、ドラッグ中に端を越えている間だけGTKのメインループへ登録します。反復間隔の初期値は50ms、移動量は端からの距離に応じて1〜6行とし、履歴の端で止めます。別スレッド、固定時間のsleep、描画完了のポーリングは使いません。これは操作を進めるタイマーであり、同期の完了待ちは既存の通知で行います。[GLibのタイマー仕様][glib-timeout]

段階5の実画面試験では、画面外への最後のマウス移動がボタン解放まで届かない場合を確認しました。GDKは既定で複数の移動イベントをまとめます。この試験では、その処理を無効にすると遅延が解消しました。左ボタン押下中は公開APIで即時配送を選び、解放・取消・表示先の破棄時に元の設定へ戻します。[GDKのイベント集約API][gdk-compression]

左ボタン解放、ESC、選択の失効、フォーカス喪失、メニュー表示、接続の終了、ウィジェット破棄・再作成でタイマーを解除します。フォーカス喪失時は、進行中の操作だけが中止の対象です。完了済みの選択表示は残します。

Ctrlを押したまま選択を伸ばしているときも、ホイールの役割は履歴移動です。runtimeが選択操作を所有している間は、presentationのCtrl＋ホイールによるズームへ先に渡さないようにします。操作していないときのズーム、端末内アプリへのマウス通知、代替画面のスクロール設定は既存の方針を保ちます。

ここでいう選択中は、左ドラッグを継続している状態です。完了済みの範囲が残っているだけなら、Ctrl＋ホイールは通常どおりズームに使います。

両形状で確認するのは、始点を残したまま画面の高さを超えて伸ばせることです。矩形は一度も表示していない履歴行も含め、boxrigの上限と文字配置の契約に従います。

### コピーと選択の失効

通常選択のコピー対象は、本文順の範囲です。矩形は物理行ごとに本文を取り出し、行間にLFを入れます。末尾に余分なLFは付けず、矩形内の空欄と末尾空白を保ちます。全角文字、結合文字、絵文字が分割・重複しないことも条件です。双方向文字は行内の論理順でコピーします。これらはboxrigのスナップショット契約に従います。[スナップショットのAPIコメント][boxrig-view]

空の矩形は操作を続けられますが、Copyは無効です。ボタン解放でPRIMARYを空文字列に置き換えません。失効した選択もコピーせず、すでに登録したクリップボードは維持します。既存のメニュー判定とコピー処理には、この振る舞いを確認するテストを追加します。

`STALE`、選択のない場合や空の矩形での`UNAVAILABLE`を、端末ウィジェットの障害に変換しません。操作中に選択本文が失われた場合はドラッグと自動スクロールを終了し、残るボタン操作を消費します。

選択行数・範囲数・コピー容量の上限超過は、途中までの本文を成功として扱いません。直前の有効な選択とクリップボードを保持し、失敗理由を報告します。期待される空・失効状態と、上限超過・メモリ不足・引数誤りは分けて処理します。[上限と更新の契約][boxrig-text]、[公開APIコメント][boxrig-view]

## 実装する段階

各段階の成果物は、起動して変化を確認できる状態が条件です。要求する動作のテストを先に追加し、旧実装での失敗を確認してから修正します。修正後は対象テストとビルドを実行し、段階ごとにコミットします。問題が出た場合は原因と計画を見直し、不要になった試行コードを残しません。

### 段階0：0.5.0への参照更新と計画保存

`deps/boxrig`を公開タグへ更新します。通常ビルドの`prepare-boxrig.mts`と、配布用ツールの`prepare-package-tools.mts`にある版番号をそろえます。上流資料へのリンクも更新対象です。日本語READMEのリンクを0.5.0へ変更し、英語READMEにも反映します。過去の計画書に残る調査時点の版番号は、そのままです。

既存の配布テストで期待するSDKの版番号を0.5.0へ変え、更新前の失敗を確認します。更新後は通常SDKの5モジュールと、移動した配布用ツールから作るSDKを検査します。後者の検査範囲は、SDKを使うプログラムのビルドと実行までです。

### 段階1：灰色の選択表示
