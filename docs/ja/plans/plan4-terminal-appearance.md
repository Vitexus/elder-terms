# 端末の視認性と外観設定の拡張計画

## 目的と保存時点の状態

スクロールバーを見分けやすくし、Settingsから端末の描画方式を確認できるようにする。
カーソル、背景透過、背景画像、色補正を設定できるようにする。

本書は2026年10月19日のコード調査に基づくplan4である。
保存時点では調査と計画の作成だけを行い、機能の実装・動作試験は行っていない。
カーソルは利用者への確認により、3形状とも入力フォーカスに応じて塗りつぶしと輪郭を切り替える仕様とした。

| 調査対象 | リビジョン・構成 |
| --- | --- |
| elder-terms | `develop`、`2a057bbe246d88d957c02abdcf89b3328ab87db5` |
| boxrig | リリース0.3.0、`3403d71e328d1a31787770d269d75c46cf8f4ad2` |
| アプリの表示構成 | Linux、GTK3、boxrigのGTK3ウィジェット |
| 描画の選択方針 | OpenGLを優先し、利用できない場合はCairoへ切り替える |
| ビルド・テスト | 既存のMakefile、npm、Meson、C++ドライバー、Vitest、gestamentを使う |

依頼文のImage #1とImage #2の画像データは、この調査では参照できていない。
したがって画像間の色差や原因を確定したとは扱わない。
スクロールバーについては現行コードから対処可能な範囲を特定し、段階1で実画面を使って再現を確認する。

## 調査結果とAPIの要否

| 要求 | 現行APIでできること | 追加対応 |
| --- | --- | --- |
| スクロールバーの視認性 | GTK標準バーのCSSで溝とつまみを個別に配色できる | 現在のGTK3構成にはboxrigの新APIは不要。アプリ側で対処する |
| Settings下部の描画方式 | `get_render_state()`で実際に描画を完了した方式と切り替え状態を取得できる | アプリ側の表示追加。X11／WaylandはGDKの接続先から取得する |
| カーソルの縦棒・下線・点滅 | `boxrig_ui_cursor_style`で形状、線幅、点滅方針を指定できる | 設定の保存と適用を追加する |
| 3形状の塗りつぶし／輪郭 | 現行の塗りつぶしは端末指定のblockに限定される | 要求を完全に満たすにはboxrigのカーソル装飾API拡張が必要 |
| 単純透過・混色 | 表示面の透過と、背景に追加するRGBA色を指定できる | GTKトップレベルの透過準備と設定UIを追加する |
| すりガラス | GTK3用background effect adapterが公開されている | 任意ライブラリのビルド・リンクと能力判定を追加する |
| 背景画像 | RGBA8画像のコピー、配置、不透明度、解除を指定できる | ファイル選択、デコード、上限検証、寿命管理を追加する |
| Oklchによる色補正 | 描画色と用途を受け取る表示先単位の色フックがある | 既存の背景色フックと統合し、アプリ側に補正関数を実装する |

boxrigの判断根拠は、固定リビジョンの[スクロールバー][boxrig-scrollbars]、[GTK統合][boxrig-gtk]、[カーソル装飾][boxrig-decorations]、[背景][boxrig-background]、[色補正][boxrig-color-filters]の公式文書である。
対応する公開ヘッダーのAPIコメントと実装も確認した。
GTKについては公式リファレンスと、インストール済みのGIRに収録されたAPIコメントを参照した。

### スクロールバー

[terminal-runtime.cpp](../../../elder-terms-terminal/src/terminal-runtime.cpp)は、`boxrig_gtk3_terminal_widget_create_scroll_container()`を使っている。
この関数は非オーバーレイの`GtkScrolledWindow`を返し、縦バーはGTKが描画する。
アプリは既に`gtk_scrolled_window_get_vscrollbar()`でバーを取得している。
boxrigの[生成関数の契約][boxrig-scroll-container-api]も、コンテナーの所有権をアプリ側に置いている。

[widget-background.cpp](../../../elder-terms-terminal/src/widget-background.cpp)には、つまみを含む部品色を背景色から導出する処理がある。
ここで使うHSL明度の変化量は`0.04`で、つまみ専用のコントラスト保証はない。
独自背景色を指定した場合の原因候補である。
背景色を指定しない場合はGTKテーマ側も調査する。

GTKの[ScrollbarのCSSノード][gtk-scrollbar]では、`trough`と`slider`を個別に指定できる。
端末のバーに専用クラスを付け、通常、hover、ドラッグ、無効状態を区別する。
他のボタンや入力欄の明度差を一律に増やさない。
表示方針、幅、adjustmentの管理は既存のboxrigとGTKに任せる。

初版では新しい配色設定を増やさず、有効なつまみと溝のコントラスト比を3:1以上にする。
これは[非テキスト要素のコントラスト指標][wcag-non-text]を参考にした製品側の受入基準である。
テーマの背景色と接続別背景色の両方で確認する。
スクロールバーはboxrigの色フック対象に含まれないため、端末本文の色補正とは別に検証する。

### カーソルAPIに不足している契約

現行の[装飾API][boxrig-decoration-api]には、端末指定へ追従する形状と、明示的なOUTLINE／BAR／UNDERLINEがある。
`block_presentation=FILL`は端末指定のblockにだけ作用する。
明示的なOUTLINE／BAR／UNDERLINEでは無視される。
縦棒と下線の中抜き表示や、フォーカスに応じた塗り分けも公開設定にはない。
これは[共通の判定処理][boxrig-cursor-implementation]と両レンダラーの描画処理でも確認できる。

上流への追加要件は、形状と塗り方を独立して指定できることである。
アプリが明示するフルボックス、縦ボックス、下線ボックスを用意する。
各形状について、フォーカスありでは塗りつぶし、なしでは同じ外形の輪郭を描けるようにする。
縦・下線の箱の太さと輪郭の線幅も分けて指定できる必要がある。

この設定は表示先だけに作用し、端末コアのDECSCUSR状態を書き換えない。
DECSCUSRは端末アプリが形状や点滅を指定する制御列である。
入力フォーカス、点滅、IME変換中の抑制、端末によるカーソル非表示を組み合わせた契約を上流で定義する。
OpenGLとCairoの双方で、文字の隠蔽属性、結合文字、双方向文字、カーソル移動後の消去も検証対象とする。

計画保存時には、上流側の実装・リリース・依存更新を別作業の前提としていた。
その後の依頼で、`~/Projects/boxrig`の`feature/cursor-enhancements`で実装し、push後に本アプリへ取り込むことが指定された。
この指示に従い、依存参照を`25ac883`へ更新した。`deps/boxrig`内のソースは直接編集していない。
追加APIは`BOXRIG_UI_CURSOR_SHAPE_BLOCK`と、全形状に作用する`presentation`、箱の太さを指定する`box_width_dip`である。
アプリでは`BOXRIG_UI_CURSOR_PRESENTATION_FOCUSED`、箱4 DIP、輪郭1 DIPを使う。
これはリリース番号を更新したものではなく、公開済みの上流コミットを固定した依存である。
取り込み時に共有ライブラリのシンボル一覧の更新漏れが見つかったため、上流で修正した。
上流側の検証には、静的ビルドに加えて`shared-gtk3`のリンク確認も含める。
独自の上描きや制御列の注入で不足を代替しない。

## 利用者から見た動作

### Settings下部の描画方式

Apply、Save、Cancelを置く下部パネルの右端に、読み取り専用の状態を表示する。
表示例は`OpenGL / X11`、`OpenGL ES / Wayland`、`Cairo / X11`とする。
OpenGL／Cairoは端末の描画方式、X11／WaylandはGTKが接続しているウィンドウシステムを表す。
XWayland上で動作する場合も、GDKがX11へ接続していればX11と表示する。

最後に描画を完了した方式を表示する。
初回描画前は「初期化中」、切り替え中は現在の方式に「切り替え中」を添える。
フォールバック後にはCairoを表示し、必要な理由はツールチップへまとめる。
`active_backend=NONE`をCairoとして扱わない。
[描画状態の定義][boxrig-render-state]を基準にする。

ボタンの順序を保ち、その右側の余白を伸縮させて状態を右寄せする。
幅が足りない場合は状態を省略表示し、全文をツールチップとアクセシビリティ情報へ残す。
Settingsを開いたときと描画状態が変わったときに更新する。
状態の更新は設定のdirty状態、Applyの可否、INI保存内容に影響させない。

ランチャーやグローバル設定など、端末の実体がない画面にはこの表示を出さない。
描画方式を選ぶ新しい設定は今回追加しない。

### カーソルの形状と点滅

Terminal設定に次の3形状と、独立した点滅ON／OFFを追加する。
ここでいうアクティブ状態は、端末が実際にキーボード入力を受けるフォーカス状態を指す。

| 形状 | アクティブ時 | 非アクティブ時 |
| --- | --- | --- |
| フルボックス | セルを塗り、下の文字も判読できるように描く | 同じセルの輪郭を描く |
| 縦ボックス | 挿入位置に縦長の箱を塗る | 同じ縦長の箱を中抜きで描く |
| 下線ボックス | セル下部の横長の箱を塗る | 同じ横長の箱を中抜きで描く |

縦ボックスの幅と下線ボックスの高さは、初期値を4 DIPとする。
DIPは表示倍率に依存しない論理的な長さである。
輪郭は1 DIPを基本とし、塗りつぶしと中抜きを見分けられる内側の面積を確保する。
セルサイズを上限としてはみ出しを防ぎ、小さいフォントでの丸めも検証する。
初版では太さの調整項目を増やさず、この既定値を100%、150%、200%相当の表示条件で目視確認する。

点滅ONではアクティブ時だけ点滅する。
非アクティブ時は輪郭を常時表示し、点滅OFFでも塗り方によって状態を区別する。
フォーカスが戻った直後は表示位相から始める。
周期はboxrigの既定である表示500 ms・非表示500 msを使う。
文字自体の点滅設定とは分離する。[点滅API][boxrig-blink-api]を参照。

利用者の形状・点滅設定を表示上はDECSCUSRより優先する。
一方、端末からのカーソル非表示とIME変換中の抑制は引き続き優先する。
カーソルの位置、入力先、端末内の状態は変更しない。

### 透過、混色、背景画像

背景モードは「不透明」「単純透過」「すりガラス」から選ぶ。
透過は端末の背景に適用し、文字、カーソル、Settings、タイトルバー、ステータスバーの判読性を保つ。
ウィンドウ全体のopacityを下げる方式は使わない。

混色は、背景画像やデスクトップに重ねる色と濃さとして設定する。
既存のGeneralの背景色は端末の標準背景色として維持する。
Terminalに追加する「混色」は独立したRGBA層であり、文字色を置き換える設定とは区別する。
背景色の不透明度、混色の濃さ、画像の不透明度も別の値として扱う。

重ねる順序は、奥から次の通りとする。

| 順序 | 層 | 設定の意味 |
| --- | --- | --- |
| 1 | デスクトップ、または不透明な下地 | 背景モードに応じて透過を許可する |
| 2 | 背景画像 | 画像自身のalphaと画像の不透明度を一度だけ掛ける |
| 3 | 混色 | 指定色と濃さをsource-overで重ねる |
| 4 | 端末のセル背景 | 背景色の不透明度を適用する |
| 5 | 文字、選択表示、端末画像、カーソル、IME | boxrig本来の描画順序と各要素のalphaを使う |

source-overは、手前の不透明度に応じて奥の色が残る合成方法である。
boxrigの[背景の合成順序][boxrig-background]に従い、alphaをアプリとライブラリで二重に掛けない。
現在の透過APIは端末背景に共通の不透明度を与えるため、ANSIで明示したセル背景も同じ対象になる。
色フックからセルごとのalphaを変更することはできない。[透過API][boxrig-background-api]と[色入力の契約][boxrig-color-api]を参照。

背景画像だけを使う場合も、画像が見えるように端末の表示面内でalpha合成を使う。
背景モードが不透明なら、GTK側の最背面を不透明に保つ。
画像に透明部分や余白があっても、デスクトップは透けない。
単純透過・すりガラスではこの下地を透明にし、同じ画像を併用できるようにする。
混色層を不透明にして画像を隠す処理で、不透明モードを実現しない。

初版の画像形式はPNGとJPEG、指定先はローカルファイルとする。
配置は「全体を埋める」「全体を収める」「引き伸ばす」を用意し、boxrigのCOVER／CONTAIN／STRETCHへ対応させる。
画像は端末領域に固定し、スクロールしても移動させない。
ファイルの選び直し、解除、Apply、Save、再起動での復元を扱う。
ファイルの自動監視や動画再生は今回の範囲に含めない。

### 透過・すりガラスの対応状態

GTK3ウィジェットが公開する透過能力は表示面の範囲である。
トップレベルからデスクトップへの透過は、elder-termsがGTKの所有者として準備する。
`NATIVE_TOPLEVEL`をウィジェットに要求して成功扱いにしない。
固定版の[GTK3初期化実装][boxrig-gtk-transparency]と[公式サンプル][boxrig-gtk-background-example]が根拠となる。

RGBA visualはトップレベルのrealize前に選ぶ。
realizeはGTKがネイティブウィンドウを生成する処理である。
起動時から透過可能な構成を用意し、不透明モードでも保持する。
これにより、実行中の切り替えで通信セッションやウィンドウを作り直さずに済む構成を目指す。
親コンテナーの背景やGTKの不透明領域指定も合わせて確認する。
[RGBA visual][gtk-rgba]と[visual設定時期][gtk-visual]の契約に従う。

| 環境 | すりガラスの条件と扱い |
| --- | --- |
| GTK3 / X11 | コンポジターとKDE方式のぼかし能力が必要。名前だけで対応を推測せずproviderの状態を読む |
| GTK3 / Wayland | `ext-background-effect-v1`のblur能力が必要。接続先の対応と探索完了を確認する |
| すりガラス未対応 | 要求は保存し、実表示は単純透過へ切り替えたことをSettings内に表示する |
| デスクトップ透過も未対応 | 不透明な下地へ切り替え、理由を表示する。背景画像と混色は継続する |

対応条件の出典は[boxrigの背景効果ガイド][boxrig-background]である。
providerはOSへぼかしを依頼するもので、`accepted`は要求の受理を示す。
実際にぼけたことは実画面で別に検証する。
初版ではぼかし半径の指定は設けない。

すりガラスは、対応時に利用するPREFER方針で要求する。
未対応環境でも端末を利用できるようにする。
要求した設定と実効状態を別に保持し、未対応だからといって保存値を変更しない。
ぼかし領域は端末の背景部分だけとする。
配置、表示倍率、map／unmap、ネイティブsurfaceの再生成に追従する。
[GTK3 adapterの契約][boxrig-background-effect-api]に従い、破棄時は要求・通知・借用資源を解放する。

### Oklchによる青色の視認性補正

色フィルターは「なし」と「青色の視認性補正（Oklch）」から選ぶ。
Oklchは、知覚上の明るさL、色の鮮やかさC、色相hで色を表す方式である。
青を明るくする際に色相を保ちやすいため、今回の補正に使う。
変換は[Oklabの原著][oklab]と[CSS Color 4のOklch・変換式][css-color]を参照する。

初版は青系の文字、独立した下線、カーソル、選択・検索・リンク・IMEのマーカーを対象にする。
背景色は比較の基準として保持する。
パレット番号だけで青を判定せず、16色、256色、true colorの解決済みRGBを同じ方針で扱う。
青系から外れる色やほぼ無彩色の色は変えない。

補正関数ではsRGBを線形RGBへ変換し、OklabからOklchへ変換する。
背景との明暗差が小さい青について、色相hを保ちながらLを調整する。
暗い背景では明るくし、明るい背景では必要な場合だけ暗くする。
適用する青の範囲には滑らかな重みを付け、境界で色が急変しないようにする。

補正後の色がsRGBで表せる範囲を超えたら、Lとhを保ってCを必要な分だけ下げる。
RGBの各成分を単純に切り詰める方法による色相の変化を避ける。
変換や探索には回数上限を設ける。
端末のパレットそのものや、コピー・ログ・OSCで問い合わせる色は変更しない。

文字のコントラスト比4.5:1を補正量の目安にする。
知覚上の明るさLとは別に、線形sRGBの相対輝度から比を計算する。
既に十分な差がある色は維持し、改善が必要な色の変化を抑える。
数値の出典は[文字のコントラスト指標][wcag-text]である。
この値だけでモニターごとの見え方や色覚上の問題を解決したとは判断しない。
青の適用範囲、Lの変更上限、鮮やかさを残す範囲は、段階7の実画面比較で決定して記録する。

色フックには背景画像やデスクトップの画素が渡されない。
カラー絵文字やKitty画像自身の画素も補正対象外である。
透過・画像使用時には、フックで分かるセル背景を基準にした補正となる。
任意の背景画像上で4.5:1を保証する機能とはしない。
必要に応じて背景色の不透明度や混色の濃さを調整できる構成とする。[色フックの制約][boxrig-color-api]を参照。

## 設定と適用の設計

### 保存項目

新しい項目は既存の`[terminal]`へ追加する。
キー名と初期値は次の案を基準とし、段階ごとの実装時に確定値を記録する。
背景効果は初期状態では無効とし、利用者が選択して有効にする。

| キー案 | 値と初期値 | 検証・扱い |
| --- | --- | --- |
| `cursor_shape` | `block`、`bar`、`underline`。初期値`block` | 未知の形状を拒否する |
| `cursor_blink` | 真偽値。初期値`true` | 形状と独立して保存する |
| `background_mode` | `opaque`、`transparent`、`blur`。初期値`opaque` | 対応能力と保存値を分離する |
| `background_opacity` | 0〜100の整数。初期値80 | 端末背景色の不透明度。不透明・画像なしでは実効値100 |
| `background_tint_color` | `#RRGGBB`。初期値`#000000` | 既存のRGB検証を使う |
| `background_tint_opacity` | 0〜100の整数。初期値0 | 0なら混色層は見えない |
| `background_image` | 絶対パス。初期値は空文字列 | 空は明示的な画像なし。継承解除とは区別する |
| `background_image_opacity` | 0〜100の整数。初期値100 | 画像自身のalphaを保つ |
| `background_image_fit` | `cover`、`contain`、`stretch`。初期値`cover` | 画像を再デコードせず配置を変更する |
| `color_filter` | `none`、`oklch-blue`。初期値`none` | 補正なしでも既存の接続別背景色は適用する |

設定値は既存のグローバル設定と接続別設定の継承に従う。
「継承する」「この接続では無効」を区別できるUIにする。
不透明モードでも画像を指定した場合は、保存した背景色の不透明度を表示面内の合成に使う。
実際のalphaは0〜255へ一度だけ変換する。

設定画面ではTerminal内を「カーソル」「背景」「色補正」に整理する。
背景画像のパスにはファイル選択と解除操作を設ける。
すべての項目をスクロールして操作でき、下部パネルは常に表示する。
既存の`settings-presentation`と翻訳カタログへラベル、説明、検証メッセージを追加する。

### Apply、Save、Cancelと失敗

Applyは実行中の端末へ反映し、ファイルへ保存しない。
Saveは検証済みの値を保存して反映する。
Cancelは未適用の編集を捨てる。
既存どおり、成功したApply／Saveの後はSettingsを閉じる。
外観の変更によって通信先へ再接続しない。

現在の[共通Settings UI](../../../shared/src/settings-widget/settings-widget.cpp)は、Applyの成功確認前に適用済みストアを更新する。
[端末側のSave](../../../elder-terms-terminal/src/main.cpp)も、保存後に実行中設定へ反映する。
画像のデコードや描画資源の準備には失敗があるため、成功・失敗・処理中をUIへ返せる契約へ変更する。
この変更は端末以外のSettings呼び出し元にも反映し、既存操作を検証する。

まず入力検証と必要な資源の準備を行う。
一連の外観設定を反映できた場合にだけ、適用済みストアとダイアログの終了を確定する。
Saveでは保存失敗も扱い、直前の表示と設定を復元できるようにする。
途中で一部だけ変更された状態や、失敗したのに成功扱いで閉じる状態を残さない。
未対応環境での仕様どおりのフォールバックは成功と区別して表示し、資源不足などの処理失敗とは分ける。

画像の読み込み中はApply／Saveを無効にし、Cancelは可能にする。
選び直しやCancel後に古い読み込みが完了しても、結果を適用しない。
破損、形式不一致、権限不足、上限超過では直前の有効な画像を保持する。
起動時に画像ファイルが失われていた場合は、画像なしの背景で端末を開く。
保存したパスを保ち、Settingsで読み込み失敗を確認できるようにする。

### 外観状態の所有と色フックの統合

設定値を読み出す型を追加し、フォントや行列数とは分離して扱う。
表示への適用は`terminal-presentation`を入口とし、色変換、画像読み込み、GTK背景効果は小さな構成要素へ委譲する。
共通Settingsライブラリにはboxrigの表示先やネイティブウィンドウの寿命管理を持ち込まない。
描画方式の表示には端末側から状態だけを渡す。

現在の[main-window.cpp](../../../elder-terms-terminal/src/main-window.cpp)の`terminal_colors()`は、既に色フックを使用している。
接続別の標準背景色と、それに対する文字・カーソル色を差し替える処理である。
色フィルター用に別のフックを登録すると、この処理を上書きしてしまう。
フックを一つにまとめ、「接続別の既定色を解決する」「選択されたOklch補正を行う」の順に適用する。

反転済みの入力を再反転しない。
下線の前景色への追従、補正済みの下地色、選択とフォーカスの状態を尊重する。
マーカーの下地へ補正を二重に適用しない。
補正OFFはOklch処理だけを解除し、既存の色指定を残す。

色フックのcontextはアプリ側が所有し、解除またはview破棄まで保持する。
設定変更時に色キャッシュを無効化し、通常のフレーム要求を使う。
コールバック中のI/O、再描画、view更新は行わない。
時刻や呼び出し順に依存しない関数とし、boxrigの色キャッシュを利用する。
[色補正の契約][boxrig-color-filters]に従う。

端末ウィジェットを再接続した場合も、カーソル、背景、画像、色フックを復元する。
前のウィジェットのcallbackや借用ポインターを残さない。
設定変更は必要な描画だけを更新し、毎フレームの画像読み込みや常時ポーリングを追加しない。

### 画像処理と追加依存

画像の入力は既存のcardioとGLibの非同期処理に合わせる。
専用ワーカースレッドや定期ポーリングは追加しない。
既存依存のGdkPixbufをデコード候補とし、[Loaderの公式文書][gdk-pixbuf-loader]とAPIコメントを確認して使う。
ファイルサイズ、画像の辺長、画素数、strideの計算を検証する。
boxrigへ渡すのは、alpha未乗算のsRGB RGBA8とする。

保持する画素の上限はboxrig既定の64 MiB、各辺は16384画素を上限とする。
デコード前後と描画資源作成時の両方で容量を確認し、加算・乗算のオーバーフローを防ぐ。
画像の置換は新しい画像の準備に成功してから行う。
成功時にはboxrigが画素をコピーするため、入力バッファを解放できる。[画像API][boxrig-background-image-api]を参照。

すりガラス用のGTK3 adapterは、現在の`shared-gtk3`／`install-shared-gtk3`だけでは組み込まれない。
上流の公開ターゲット`install-background-gtk3`と、そのWayland依存を使う。
現行SDKでは静的アーカイブなので、`pkg-config --static`相当で私的依存も解決する。
X11、Xfixes、Waylandのリンク条件とライセンス・配布物を確認する。[adapterのビルド定義][boxrig-effect-build]を参照。

変更対象はアプリ側の`scripts/prepare-boxrig.mts`、ルートの`meson.build`、パッケージ準備と依存一覧である。
通常ビルドと配布用ツール準備の両方に反映する。
管理者権限が必要な開発パッケージの追加が判明した場合は、インストールを利用者へ依頼する。

内部処理の説明は本計画に置き、READMEは利用者の操作を中心にする。

通常ビルドを警告なしで完了し、ルートの`npm test`を必ず実行する。
現在サポートする配布対象について追加依存の解決を確認する。
環境依存の試験を実行できなかった場合は、対象と理由を残す。
すりガラスの対応環境での実表示など、必須の確認が残る機能は未完了とする。

完了条件は次節の一覧をすべて満たすことである。
成果は`fix:`、`chore:`、`doc:`を使って内容ごとにコミットする。
明示的な指示があるまでmainへのマージは行わない。

## 検証方法と全体の完了条件

| 検証対象 | 主な方法 |
| --- | --- |
| 設定値・継承・保存 | `shared/tests/settings-test.cpp`とSettingsのVitest試験を拡張する |
| フッター表示・入力操作 | gestamentで実際のSettingsを操作し、文字列、配置、dirty状態を検査する |
| スクロールバー | 実ウィジェットの画素、コントラスト、履歴移動を検査する |
| カーソル | C++ドライバーとGUI録画で外形、内部画素、フォーカス、点滅遷移を検査する |
| 背景合成 | 既知の画像と背後ウィンドウを使い、alphaと配置を画素で検査する |
| すりガラス | providerの状態試験と、対応コンポジターでの実画面試験を分ける |
| 色フィルター | 数値試験、実描画、元の端末状態の不変性を検査する |
| ライフサイクル | 選び直し、失敗、Cancel、ウィジェット再接続、ウィンドウ終了を検査する |
| 描画方式・表示環境 | OpenGL／CairoとX11／Waylandを組み合わせる。OpenGL ESは利用可能な環境で追加する |
| 性能と回帰 | plan3と同条件の比較、既存の全体テスト、配布用ビルドを実施する |

既存の`boxrig-main-layout.test.ts`には録画と画素検査の例がある。
時間軸の試験はこの仕組みを参考にし、一定時間sleepした後の1枚だけで判断しない。
描画世代・準備完了・観測した位相を使って待機し、タイムアウトは失敗を検出する上限として扱う。
動画から必要な状態遷移を読み直してアサートする。
Xvfbだけでは実コンポジターによる透過・ぼかしを証明できないため、対応環境の検証を別途行う。

- スクロールバーのAPI要否と原因の切り分けを記録し、つまみを背景から識別できる。
- Settings下部の右端に、実際の描画方式とウィンドウシステムが表示される。
- 全3形状でフォーカスに応じた塗りつぶし／輪郭と、独立した点滅ON／OFFを使える。
- 単純透過とすりガラスを選べ、混色の色と濃さを指定できる。
- 背景画像を単独でも透過と組み合わせても使用できる。
- Oklch補正を色フック経由で選べ、青の判読性と色相保持を確認できる。
- 継承、Apply、Save、Cancel、再起動、失敗時の復元が一貫している。
- 未対応状態を正しく表示し、通信・入力・コピー・ログを変更しない。
- 必要な実画面・動画・画像の確認、警告なしのビルド、全体テスト、配布確認が完了している。
- 各段階をコミットし、検証結果と残件を本書へ追記している。

## この計画を保存する作業の完了条件

今回の作業範囲は調査とplan4の保存である。
上記の実装完了条件とは分けて扱う。
6項目の要求、現在のコードとの対応、APIの要否、フォーカス表示の確認結果を記載する。
各段階に観測できる成果物と完了条件を置き、外部依存の制約に出典を付ける。
文書のリンク、差分、日本語表現を検査して`doc:`コミットを作成する。
